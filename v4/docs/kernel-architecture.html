Actualizado: Marzo 2026 | Certificación: 43/43 Tests Superados

1. Visión General

El Kernel (js/core/store.js) actúa como el cerebro central (State Manager) de la aplicación TeamTowers. Gestiona el estado global de la DAO, la seguridad, la jerarquía de permisos (RBAC), la contabilidad inmutable de las aportaciones y la inyección de contexto para la IA.

2. Estructura del Estado (initialState)

La base de datos en memoria está dividida en 6 grandes bloques:

  • config: Configuración global del ecosistema (tema, nombre, prompt IA).
  • ontology: Diccionario de sectores y roles. Guarda multiplicadores, FMV y entregables estándar. Soporta inyección dinámica.
  • globalUsers: Pool de identidad. Directorio de todos los usuarios registrados.
  • macroFlows: Trazabilidad de intercambios de valor inter-proyectos.
  • projects: El corazón del sistema. Cada red con su estructura (roles, asignaciones, ledger, transacciones, alertas).
  • session: Control de acceso global (admin o user).

3. Módulos y Funcionalidades Clave

🔐 Seguridad y RBAC

  • Control de Identidad: Bloqueo de @id duplicados en el Pool Global.
  • Gobernanza: Solo el admin puede instanciar redes nuevas, salvo excepciones de flujo controlado (bypass).
  • Delegación: Propiedad de proyecto delegable mediante PROMOTE_TO_PO.

🧬 Ontologías Dinámicas

  • Parser Universal: Acepta formatos Array, Objeto Clásico (Legacy) o Diccionarios Anidados.
  • Fallback de Supervivencia: Si se inyecta una ontología vacía, el Kernel crea un Mínimo Viable o la matriz de Marketing para evitar colapsos.

⛓️ Contabilidad Criptográfica (Triple Entrada)

  • Chaining de Hashes: Cada transacción consolidada inscribe el hash del bloque anterior como prevHash en el nuevo bloque del Ledger.
  • Value Accounting: Valor = Horas × FMV × Multiplicador de Rol × Multiplicador de Arquetipo.

🧠 Módulo INTEL

  • Generación de prompts dinámicos con Secuenciación Temporal y Personalización de Roles según la fase activa del proyecto.

4. Acciones Principales (Reducers)

  • ADD_PROJECT: Instancia un proyecto (parseo de ontología, RBAC y Owner).
  • ADD_TRANSACTION / REPORT_TRANSACTION: Motor del Pull System.
  • APPROVE_TRANSACTION: Convierte trabajo en valor consolidado (Ledger sellado).
  • ASSIGN_USER_ROLE: Vincula ID global a Rol local.
