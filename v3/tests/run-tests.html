🏗️ VISIÓN DEL SISTEMA
TeamTowers Humà v3.1 es un sistema de contabilidad de valor y gestión del conocimiento basado en principios de economía organizacional. El kernel gestiona proyectos, roles, usuarios y transacciones con un store centralizado y selectors para cálculos derivados. La arquitectura sigue los principios de Equilibri (balance), Seny (sensatez), Força (robustez) y Valor (generación de valor).
Última modificación: 22/02/2026 | Versión: 3.1 | Responsable: @arquitecto
📊 ESTRUCTURA DE DATOS
El store central (store.js) mantiene el estado con cuatro colecciones principales: - projects: Array de proyectos con id, name, sector - roles: Array de roles con id, name, multiplier, color - users: Array de usuarios con id, name, type (human/ai) - transactions: Array de transacciones con id, name, project, role, user, uv, date Los selectors (selectors.js) proporcionan cálculos derivados: getGlobalMetrics(), getProjectsWithMetrics(), getTopContributors(), getTransactionsByProject().
Última modificación: 22/02/2026 | Versión: 1.2 | Responsable: @arquitecto
🧪 PROTOCOLO DE TESTS
El sistema de tests se organiza en cuatro niveles: 1. Unit Tests: Verifican componentes individuales (store, selectors) 2. Integration Tests: Validan flujos completos (dashboard, navegación) 3. Regression Tests: Aseguran que el kernel no se rompe 4. Audit Tests: Miden rendimiento (<16ms), aislamiento, manejo de errores y compatibilidad móvil El runner (run-tests.html) proporciona una interfaz visual para ejecutar todos los tests y ver resultados en tiempo real.
Última modificación: 22/02/2026 | Versión: 1.0 | Responsable: @arquitecto
📱 PRINCIPIOS MOBILE FIRST
Todos los componentes y tests están diseñados para funcionar en dispositivos móviles: - Botones con altura mínima de 48px para interacción táctil - Fuente base de 16px para legibilidad - Layouts flexibles con clamp() y porcentajes - Tests específicos que validan la experiencia móvil - Soporte para hover: none con feedback táctil

⚙️ KERNEL CRÍTICO
El kernel del sistema está formado por: 1. store.js - Estado central inmutable con getState() y listeners 2. selectors.js - Cálculos derivados puros 3. router.js - Navegación SPA con deep linking 4. dashboard.js - Página principal con métricas globales 5. projects.js - Listado de proyectos con filtros 6. users.js - Gestión de usuarios y top contributors Todos los componentes se comunican mediante eventos, nunca acceden directamente al store.
